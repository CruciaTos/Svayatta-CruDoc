# UI audit: what doesn't match the current UI (23 Oct 2026)

"Current UI" = Calm Clinical (`.claude/rules/crudoc-ui.md`, `design/dashboard-redesign/DESIGN_SPEC.md`): Cru tokens and widgets, Geist, Ink Blue as the only blue, Day and Evening. On the phone, the phone kit (`mobile_kit.dart`).

**How this was checked.** Every widget file in `lib/` (329 files) was scanned for hard-coded colours, raw font sizes and radii, stock Material buttons, dialogs and icons, the old `AppColors` palette and font, and screens pinned to the Day theme. An import graph from `main.dart` then separated what users can reach from dead code, and the worst live screens were read by hand. This is a code audit, not a screenshot-by-screenshot pass.

## Progress

- [x] **One toast style app-wide.** It comes from the theme (`CruTheme` → `snackBarTheme`): label ink, Geist, floating, 12 px corners, Day and Evening. Every forced red, green, slate or blue toast now uses it (about 20 call sites).
- [x] **Plain Material dialogs take the card look** (`dialogTheme`). This covers the stock `AlertDialog`s in row 13 until they are rebuilt.
- [x] **Help & shortcuts rebuilt**, with current shortcuts, voice keys and buttons for both tours (desktop row 9).
- [x] **Item page rebuilt** (desktop row 5). Edit opens the new item dialog, and the page now follows Edit and Adjust stock live. The old `add_edit_medicine_form.dart` is dead code now.
- [x] **Visit details rebuilt** (desktop row 4). No more Day pin; grey monogram, neutral status pills, segmented status control.
- [ ] Revenue → Invoices tab (desktop row 2; phone row 3)
- [ ] Inventory → Orders, Vendors, Usage (desktop row 3)
- [ ] Campaigns, desktop and phone (desktop row 1; phone row 2)
- [ ] Phone Add / Edit patient (phone row 1)
- [ ] Plan surfaces, clinic switcher, "Not in your plan" (desktop rows 6–8)
- [ ] Homeopathy, voice bar, address field and map (desktop rows 10–12)
- [ ] Spec decisions (section 3) and dead-code removal (section 4)

## Summary

- **Matches the current UI:** Dashboard, sidebar, Patients (list and details), Schedule (calendar and Live), check-in, Inventory items, Revenue overview, the new patient / appointment / item / payment / invoice dialogs, Settings, Team, Files, Scribe, Radiology, Dental desktop, Auth, Onboarding, the phone tabs and the tour.
- **Still on the old UI and reachable:** 14 desktop screens and dialogs and 6 phone ones (below). Together about 22,000 lines (counting whole files; a few are only partly used).
- **Dead code:** 40 old screens (about 27,600 lines) that nothing in the app opens anymore.
- **Two fonts:** 13 live files still use Plus Jakarta Sans (`AppColors.bodyFontFamily`) instead of Geist.
- **Day only:** 3 places force the Day theme, so they stay light in Evening: Campaigns, Revenue → Invoices, Visit details.

## 3. Redesigned screens that break a spec rule

| Where | File | Rule broken |
|---|---|---|
| **Sidebar (Day)** | `shell/components/cru_sidebar.dart` | The spec says the sidebar has no card behind it and sits on the canvas. Day draws a blue gradient card `#1E3A8A → #1F4FCB`: a second blue. The profile card hard-codes `#0F172A` / `#475569`, and the sun icon is amber `#F59E0B` (amber means waiting). |
| **Up next card** | `dashboard/presentation/widgets/up_next_card.dart` | "UP NEXT" in 11 px bold caps with letter spacing (the spec says "Up next", 600). It uses the sparkle icon, which means AI elsewhere. The wait pill hard-codes amber `#FEF3C7` / `#92400E`, the token number is set at 22 px weight 900, and the labels are light blues `#93C5FD` / `#BFDBFE` instead of the on-ink tokens. |
| **Phone colours** | `mobile/mobile_kit.dart` (`MobileBlue`), `mobile_nav_bar.dart`, `mobile_backdrop.dart` | The phone has its own palette (Neon `#3960FB`, Penn `#142258`, lavender, periwinkle) and a gradient nav bar. That's a second blue system next to Ink Blue. If the phone look is intentional, add it to the spec; if not, map it onto the tokens. |
| **Error toasts in red** | `revenue/.../desktop_invoices_screen.dart:1213`, `invoices_screen.dart:1020`, `subscription/.../payment_checkout_sheet.dart:154`, and a few more | Red is for allergies and patient safety only. |
| **Toasts in general** | many | Three styles: the styled one in Settings (`_toast`), the plain Material one in `mobileSay`, and dozens of raw `SnackBar(content: Text(...))` calls. There is no shared toast. |
| **Dashboard cards** | `dashboard/.../schedule_card.dart`, `side_cards.dart` | A few hard-coded colours (4 and 3). Small; check them against the tokens. |

## 5. Suggested order

1. **Quick fixes (an hour or two):** rewrite the Help & shortcuts dialog (stale copy). Swap red error toasts for the neutral toast. Add one shared `cruToast` and use it everywhere.
2. **Desktop tabs people open daily:** Revenue → Invoices, Visit details, Inventory Orders / Vendors / Usage, Item details + Edit (point Edit at the new dialog).
3. **Campaigns tab** and its compose / analytics dialogs, desktop and phone.
4. **Phone Add / Edit patient** as a phone-kit page; then remove the duplicate `AddPatientSheet`.
5. **Plan and upsell surfaces:** upgrade sheet, checkout, "Not in your plan", clinic switcher.
6. **Decide on the spec questions:** sidebar gradient, Up next styling, the phone palette. Either change the code or update the spec.
7. **Delete the dead code** in section 4, then remove `AppColors` and the Plus Jakarta Sans font once nothing live uses them.
